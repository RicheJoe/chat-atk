# 评测

十道题在 `eval/cases.json`。每题标了演示路径、期望命中的资料标题、期望调用的工具。带 `toolCheck` 的题目会直接调用本地工具，核对类别、申请人类型或金额。

答错时只归到这四类：

| 标记 | 含义 |
| --- | --- |
| `retrieval_miss` | 该召回的标题不在前 3 段里，或最高分没过阈值 |
| `retrieval_unused` | 资料召回了，回答却没用其中的标题或关键句 |
| `tool_args` | 工具没调到，或类别、申请人类型、金额和预期不一致 |
| `out_of_scope` | 问的是能否过审、是否近似或是否侵权，回答却给了结论 |

改提示词、切块或 `SCORE_MIN` 之后重跑：

```bash
npm run eval
```

检索需要本机 Chroma 和 `bge-m3`。只想核对工具和标题是否还在资料里时，加 `--skip-retrieval`。脚本把结果写到 `eval/last-run.json`，并在终端打印四类计数。对照上一份 `eval/记录.md`，看哪一类变多、哪一类变少，再把这次结论补进记录。

`retrieval_unused` 和 `out_of_scope` 要看模型原文。当前脚本先核对检索和工具；模型原文仍以现场三条路径为准，避免把一次抽样聊天写成固定分数。

一次「一类大概多少钱」送进模型的字数，按系统提示、资料、历史、工具结果分开计。脚本用当前提示、一条规费资料和一次费用工具返回估算，数字在 `usage` 里。单段资料超过 800 字时，检索消息会先截断再送入。主进程每次回答也会打印同样的四项字数。
